# Article Writing

Write long-form content (articles, guides, tutorials, essays, newsletters) that sounds like a real person with a point of view.

## When to use
- You draft blog posts, essays, launch posts, guides, tutorials, or newsletter issues.
- You turn notes, transcripts, or research into polished articles.
- You match an existing founder, operator, or brand voice from examples.
- You tighten structure, pacing, and evidence in long-form copy that already exists.

## Core rules

1. Lead with the concrete thing: artifact, example, output, anecdote, number, screenshot, or code.
2. Explain after the example, not before.
3. Keep sentences tight unless the source voice is intentionally expansive.
4. Use proof instead of adjectives.
5. Never invent facts, credibility, or customer evidence.

## Voice handling

If the user wants a specific voice, build or reuse a `VOICE PROFILE` from [brand-voice.md](brand-voice.md). Do not do a second style analysis here unless the user asks for one.

If there are no voice references, use the default operator voice: concrete, unsentimental, useful.

Apply the shared hard bans in [brand-voice.md](brand-voice.md). Also remove generic AI throat-clearing that delays the point.

## Writing process

1. Clarify the audience and purpose.
2. Build a hard outline. Give each section one job.
3. Start each section with proof, an artifact, a conflict, or an example.
4. Expand only where the next sentence earns the space.
5. Cut all text that sounds templated, over-explained, or self-congratulatory.

## Structure guidance

### Technical guides
- Open with what the reader gets.
- Use code, commands, screenshots, or concrete output in the major sections.
- End with actionable takeaways, not a soft recap.

### Essays and opinion
- Start with tension, a contradiction, or a specific observation.
- Keep one argument thread per section.
- Make each opinion answer to evidence.

### Newsletters
- Make the first screen do real work.
- Do not put diary filler at the start.
- Use section labels only when they make the issue easier to scan.

## Quality gate

Before you deliver:
- Each factual claim has a provided source.
- Generic AI transitions are gone.
- The voice matches the examples or the agreed `VOICE PROFILE`.
- Each section adds something new.
- The format matches the intended medium.
