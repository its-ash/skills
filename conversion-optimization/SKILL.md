# Conversion Optimization

**Purpose** – Provide a systematic, high‑impact audit and improvement plan for any conversion‑focused asset: marketing pages, lead/contact forms, pop‑ups, signup/registration flows, onboarding experiences, and in‑app paywalls/upgrade screens.

---

## When to Use
- You hear “CRO”, “conversion rate optimization”, “page isn’t converting”, “form friction”, “signup drop‑off”, “onboarding activation”, or “upgrade prompt”.
- The asset is a homepage, landing page, pricing/feature page, blog post, lead/contact/demo form, modal/popup, signup or registration flow, onboarding checklist, or paywall/upgrade screen.
- You need an audit, quick‑win list, high‑impact roadmap, or A/B‑test hypotheses.

---

## Initial Assessment (common to all assets)
1. **Asset Type** – Page, Form, Popup, Signup Flow, Onboarding, Paywall.
2. **Primary Conversion Goal** – Sign‑up, demo request, purchase, newsletter, download, upgrade, etc.
3. **Traffic Context** – Source (organic, paid, email, referral), device mix, new vs. returning.
4. **Current Metrics** – Conversion rate, drop‑off points, time to complete, error rates.
5. **Business Constraints** – Required data, compliance, technical limits, brand tone.

---

## Core CRO Principles (apply to every asset)
- **Show Value Before Asking** – Demonstrate the benefit first; the ask (CTA, form, upgrade) follows.
- **Minimize Required Fields / Steps** – Every extra field or step reduces conversion. Keep only what is essential now; collect the rest later (progressive profiling).
- **Reduce Cognitive Load** – One question per field, clear labels, logical grouping, smart defaults, and inline validation.
- **Respect the User** – Easy dismiss, no dark patterns, clear escape hatch, frequency capping, and accessibility.
- **Visual Hierarchy & Scannability** – Most important elements (headline, value, CTA) must be prominent and above the fold.
- **Trust & Social Proof** – Logos, testimonials, security badges, privacy statements placed near the CTA.
- **Objection Handling** – FAQs, guarantees, pricing clarity, and risk‑reversal copy.
- **Progress & Motivation** – Checklists, progress bars, celebration messages, and clear next steps.
- **Timing & Triggers** – Show pop‑ups, paywalls, or upgrade prompts after the user has experienced value (aha moment) or reached a friction point.
- **Mobile‑First** – Touch‑target size ≥44 px, appropriate keyboards, single‑column layout, and fast load.

## Asset‑Specific Frameworks
### 1. Page CRO (homepage, landing, pricing, feature, blog)
| Dimension | What to Check | Quick‑Win Tips |
|---|---|---|
| **Value Proposition** | Can a visitor grasp the core benefit in ≤5 seconds? | Rewrite headline to be outcome‑focused; remove jargon. |
| **Headline** | Communicates core value, specific, matches ad copy. | Test headline with numbers or social proof (e.g., “Join 12 000+ teams”). |
| **CTA Placement & Copy** | One primary CTA, visible above the fold, value‑oriented text. | Change “Submit” → “Start Free Trial”. Add secondary CTA after key sections. |
| **Visual Hierarchy** | Clear H1 → H2 → body, ample white space, images support message. | Add spacing, use larger font for benefit statements, replace stock photos with product screenshots. |
| **Trust Signals** | Logos, testimonials, review scores near CTA. | Insert a “Trusted by” strip right above the primary CTA. |
| **Objection Handling** | FAQ, guarantees, pricing clarity. | Add a short FAQ accordion below the fold. |
| **Friction Points** | Slow load, hidden navigation, too many links. | Reduce page weight, hide navigation on single‑purpose landing pages. |
| **Test Ideas** | A/B headline, CTA color, hero image vs. video, “Most Popular” badge on pricing. |

### 2. Form CRO (lead capture, contact, demo, quote, survey, checkout)
- **Field Cost Rule** – 3 fields = baseline; 4‑6 fields → 10‑25 % drop; 7+ fields → 25‑50 % drop.
- **Essential Fields** – Email (or phone) + password (if signup) + one optional name field.
- **Field‑by‑Field Guidance**
  - **Email** – Single field, inline validation, typo detection, mobile email keyboard.
  - **Name** – Prefer single “Full name” field; split only if needed for personalization.
  - **Phone** – Make optional; auto‑format, show country code picker.
  - **Company** – Auto‑suggest, enrich after submission.
  - **Dropdowns / Radio** – Use searchable dropdowns for >5 options; keep labels visible.
- **Layout** – Single‑column on all devices; 2‑column only for short, related fields (first/last name).
- **Multi‑Step Forms** – Use when >5 fields or logical sections. Show progress bar, start with easy questions, allow back navigation, save progress.
- **Error Handling** – Inline validation, specific messages, focus on first error, never clear entered data.
- **Submit Button** – Action‑plus‑benefit copy (e.g., “Get My Free Quote”). Prominent contrast, size ≥44 px.
- **Trust Elements** – Privacy note, security badge, expected response time.
- **Mobile Optimizations** – Larger tap targets, appropriate keyboards, sticky submit button.
- **Metrics** – Form start rate, completion rate, field‑level drop‑off, error rate, time to complete.

### 3. Popup / Modal CRO
- **Trigger Strategies**
  - **Scroll‑Based** – 25‑50 % depth for blogs.
  - **Exit‑Intent** – Desktop cursor moving to close; mobile use back‑scroll or time‑delay.
  - **Time‑Delay** – 30‑60 s after page load (avoid <10 s).
  - **Click‑Triggered** – User‑initiated, zero annoyance.
  - **Behavior‑Based** – Cart abandonment, pricing‑page visit, repeat visits.
- **Design** – Headline > value > form/CTA > close button. Width 400‑600 px desktop; full‑width bottom or centered on mobile. Close button always visible; “No thanks” link.
- **Copy Formulas** – Benefit‑driven headline, concise subhead, specific CTA, privacy reassurance.
- **Frequency Capping** – Show once per session, respect dismiss for 7‑30 days.
- **Compliance** – GDPR consent if collecting personal data; accessible (keyboard, screen‑reader). 
- **Metrics** – Impressions, conversion, close rate, time to close.

### 4. Signup Flow CRO
- **Field Prioritization** – Email/phone + password are essential. Name optional; company, role, phone defer to onboarding.
- **Social Auth** – Place prominently; often higher conversion than email.
- **Single‑Step vs. Multi‑Step** – ≤3 fields → single step; >3 → multi‑step with progress indicator.
- **Trust Signals** – “No credit card required”, privacy note, security badge, testimonial.
- **Error Handling** – Inline validation, clear messages, keep entered data.
- **Mobile** – Large tap targets, autofill, social auth, sticky CTA.
- **Post‑Submit** – Immediate confirmation, next‑step preview, optional email verification (delay if possible).

### 5. Onboarding CRO
- **Define the Aha Moment** – The first action that predicts long‑term retention.
- **One Goal per Session** – Focus on a single successful outcome; defer secondary features.
- **Do‑Not‑Show** – Prefer interactive tasks over static tutorials.
- **Checklist Pattern** – 3‑7 high‑value items, ordered by impact, progress bar, celebration on completion.
- **Empty States** – Explain purpose, show preview, primary CTA to create first item.
- **Tooltips / Tours** – ≤5 steps, dismissable, not shown to returning users.
- **Multi‑Channel** – Welcome email, in‑app reminders, push notifications (timed, not immediate).
- **Metrics** – Activation rate, time to activation, onboarding completion, early retention (Day 1/7/30).

### 6. Paywall / Upgrade Screen CRO
- **Timing** – Show only after the user has experienced real value (post‑aha or when hitting a limit).
- **Headline** – Benefit‑focused (“Unlock unlimited projects”). Avoid price‑first headlines.
- **Value Demonstration** – Preview of paid feature, before/after, or ROI example.
- **Feature Comparison** – Highlight key differences, mark recommended plan.
- **Pricing** – Simple, clear, annual vs. monthly toggle, per‑seat clarity.
- **CTA** – Action + benefit (“Upgrade to Pro – Get Unlimited”).
- **Escape Hatch** – Clear “Maybe later” or “Continue with Free” link; no guilt‑trip language.
- **Friction‑Free Path** – In‑context upgrade, pre‑filled info, minimal steps, security badges.
- **Mobile** – Full‑screen acceptable, swipe‑to‑dismiss, large tap targets.
- **Frequency** – Limit to 1‑2 prompts per session; cool‑down after dismiss (days).
- **Metrics** – Paywall impressions, click‑through, upgrade completion, revenue per user, churn after upgrade.

## Checklist for a CRO Audit
- [ ] Identify asset type and primary conversion goal.
- [ ] Record current conversion metrics and drop‑off points.
- [ ] Verify value proposition is clear within 5 seconds.
- [ ] Evaluate headline for specificity and relevance.
- [ ] Ensure a single, prominent CTA with value‑oriented copy.
- [ ] Count form fields; remove any non‑essential.
- [ ] Check inline validation and error messages.
- [ ] Add trust signals (logos, badges, privacy note) near CTA.
- [ ] Review visual hierarchy and white‑space balance.
- [ ] Test timing/trigger (scroll, exit‑intent, time‑delay) for pop‑ups/paywalls.
- [ ] Confirm mobile friendliness (touch targets, single column, fast load).
- [ ] Set up measurement: start rate, completion rate, per‑field drop‑off, activation, upgrade.
- [ ] Draft 2‑3 A/B test hypotheses with expected lift.

---

## Output Format for Recommendations
Provide the audit in four sections:
1. **Quick Wins** – Easy changes that can be deployed today.
2. **High‑Impact Changes** – Larger redesigns or new flows.
3. **Test Ideas** – Specific A/B hypotheses (e.g., headline A vs. B, CTA color, multi‑step vs. single‑step).
4. **Copy Alternatives** – 2‑3 variants for headlines, CTAs, value props with brief rationale.
